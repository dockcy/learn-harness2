# 序章 · 大纲｜先看全景：一张图读懂 Harness²

对应源码：[core/schedule.py](https://github.com/google-research/harness2/blob/main/harness2/core/schedule.py)、[core/recursion.py](https://github.com/google-research/harness2/blob/main/harness2/core/recursion.py)

一句话：**模型权重一个都不改**。每遇到一个没见过的新任务，先让模型照常干几遍，读这些执行记录，用“**提议 → 试探 → 合成**”改进这次任务的 **harness（马具）**，再**蒙着眼**挑出最好的一版交付；最后把**有证据撑腰的经验**写进按领域划分的经验库，**带给下一个任务**。

### 名字里的“²”：两层递归

Harness² 读作 “Harness 平方”。“平方”指的是两层套在一起的改进循环，它们都不碰模型权重：

|  | 第一层：任务级递归 | 第二层：改进级递归 |
| --- | --- | --- |
| 英文原名 | Task-level recursion | Harnessing-level recursion |
| 改的是什么 | 这一个任务用的**执行 harness**（给干活的代理用） | 跨任务保存的**改进 harness**：经验库里的成品 harness 和经验条目（给“改马具的人”用） |
| 怎么改 | 提议—试探—合成（Propose–Probe–Compose），全程没有标准答案 | 每个任务结束后反思：哪些改动真起了作用，写成一条可迁移的经验 |
| 作用范围 | 只在当前任务内 | 同一领域里，后面的每一个任务 |
| 对应章节 | 第 2、3、4、6、8 站 | 第 5 站 |

### 优先级：先学什么，后学什么

**P0 核心主干 · 必学**第 1–5 站。弄懂“改什么（八个组件）→ 怎么改（提议·试探·合成）→ 往哪改（INV / DOM）→ 怎么挑（盲选）→ 怎么传（经验库）”，就能讲清整个项目。

**P1 关键约束 · 想用好就要懂**第 6–9 站。预算怎么分、怎样做到全程碰不到答案、编辑结果怎么校验、证据怎么递交。这些约束决定了方法“可信”。

**P2 工程地基 · 想改代码再读**第 10–12 站。接口怎么解耦、配置怎么防错、并发与断点续跑。想接入自己的基准或执行器时必读。

### 12 站，每站带着一个问题

| 站 | 寓言 | 带着的问题 |
| --- | --- | --- |
| 1 | 《不能换马的驿站》 | 不许改模型权重，那到底能改什么？ |
| 2 | 《没有考官的厨房》 | 没有标准答案，怎么知道一处改动有没有用？ |
| 3 | 《钟楼的两把钥匙》 | 改动应该往哪两个方向去想？ |
| 4 | 《蒙眼品酒会》 | 改出好几版，交哪一版？谁来挑、怎么挑才公平？ |
| 5 | 《老船长的航海日志》 | 怎样让下一个任务真正受益，而不是被带偏？ |
| 6 | 《一样多的铲子》 | 预算一样，是铺开试，还是一层层往深里挖？ |
| 7 | 《挂铃铛的丝线》 | 怎么保证从头到尾碰不到答案和评分？ |
| 8 | 《只标改动的裁缝》 | 编辑器交回的修改，怎么防止它把东西改坏？ |
| 9 | 《档案室里的那张纸条》 | 证据怎么递给编辑器，又不被证据里的话“带跑”？ |
| 10 | 《打更人的招募告示》 | 换一个基准、换一个执行器，要改多少代码？ |
| 11 | 《刻进石碑的章程》 | 配置写错了，最早能在什么时候发现？ |
| 12 | 《同时出发的信使》 | 并发跑会不会乱？跑到一半断了怎么办？ |

**它到底有没有用？（来自项目 README）**只做**一步** Harness²，就能让 GLM-5 和 Gemini 3.5 Flash 超过它们的基础 harness：WorkBuddy-Bench 最多提升 11.5 分，JobBench 4.5 分，LAB 的部分通过率提升 11.8 个百分点；加大任务级递归的预算 k，还能继续涨。官方支持三个基准（JobBench、LAB、WorkBuddy-Bench）和两个执行器（默认 OpenCode，加 `--substrate cx` 换成 Codex）。

**序章小结**

- Harness² = 冻结模型 + 可编辑的 harness + 两层递归。
- 主干只有五件事：**改什么、怎么改、往哪改、怎么挑、怎么传**——就是 P0 的五站。
- 代码上，方法核心集中在 `core/recursion.py`、`selection.py`、`library.py`、`prompts.py`、`tree.py` 五个文件。
