钟楼的两把钥匙

修钟匠老许一年到头在路上，哪个镇子的钟楼出了毛病，就请他去。每个镇子他都是头一回去。

他带两个徒弟，各发一把钥匙。铜钥匙开机芯舱：发条、齿轮、擒纵，一座钟“怎么走”全在里面。银钥匙开镇公所的历书柜：这个镇子的节气、集日、什么时辰敲几下，一座钟“该怎么报”全在里面。

老许定了条死规矩：“各管各的锁。拿铜钥匙的不许翻历书，拿银钥匙的不许碰齿轮。”

这回到了青石镇。拿铜钥匙的大徒弟发现，机芯每晚都在同一颗齿上打滑。他想装个卡簧，老许拦住了：“先用最省事的法子。只是上弦顺序错了，就在舱门上贴张条子；要是每天都得数一遍齿，就做个量规；冬至才用得上的那套校准，装进信封写上‘冬至拆’；只有贴了条子还反复被人无视，才上锁扣——而且锁扣不能把正常上弦也锁死。”

拿银钥匙的二徒弟发现，青石镇按旧历赶集，集日要连敲三下，这座钟对此一无所知。他把集日规矩誊进历书。老许翻了翻，又提了两点：“这页规矩，写成‘逢集日翻到这页’，别抄到历书扉页上——扉页人人每天都要念，多一行就得删一行。还有，‘今年腊月初八有庙会’别往里写，那是今年的事，明年就成了错的。”

临走前，老许把两个徒弟的改法合在一起，又在箱子里留了张单子给下一个镇子：哪些是青石镇才有的，哪些是到哪都用得上的，分开写，标清楚。

猜一猜：铜钥匙和银钥匙，对应 Harness² 里哪两个“提议方向”？

谜底：INV 与 DOM —— 两个分工明确的提议维度

INV（铜钥匙）管“代理怎么干活”：流程、工具使用、怎样算做完——不碰专业内容。DOM（银钥匙）管“行家知道什么”：交付物该长什么样、给谁看、为谁做决定、权威来源、必备结构、一致性关系、行家知道要省掉什么——不碰流程。两类编辑器读同一份证据、各出一版候选，最后由合成器合并。

INV：失败类型 → 最便宜的有效部件

INV 编辑器的任务是：顺着流程找到最早出现的偏差，把每个失败对应到最便宜的有效部件。

失败类型该怎么改落到哪个部件
工具报错 TOOL ERROR先分清是输入错、超时、能力缺失、权限还是没读输出；给一个有边界的备选方案和停止条件，绝不规定盲目重试常驻提示 / 工具说明
机械重复 MECHANICAL REPETITION重复的确定性抽取、转换、核对，写成有明确输入输出和失败行为的脚本C7 scripts/<名>.py
触发式流程 TRIGGERED WORKFLOW窄而多步的流程做成按需技能，在常驻文字里写明触发条件，并带上它需要的脚本C6 技能 + 触发行
被无视的硬规矩 IGNORED INVARIANT只有反复证据表明清楚的文字被跳过，才上防御性杠杆；不能挡住正常完成C8 插件（Codex 为钩子）
普通的先后顺序 ORDINARY SEQUENCING简洁的常驻指引；一次性的错误不写代码，也不要把专业判断自动化C1 / C2 常驻文字

INV 还有一条收尾要求：要定义什么叫“证据够了”，给每个交付物留出余量，并重新打开或机械检查交付物——“a successful write call does not establish usability”（写入成功不等于可用）。

DOM：把行家知识变成可检查的规则

规则形式要写清什么
分析动作 ANALYTIC MOVE点名操作——比较、核对、计算、分类、追溯、起草、解释——它的输入和要求的结果
交付物契约 ARTIFACT CONTRACT必备部分、部分之间的依赖，以及一致性和实用性的领域检查
决策规则 DECISION RULE触发条件、支持证据、要解决的冲突、必须明说的不确定性
编码形式 ENCODING形式和内容一样要斟酌：有明确触发场景的领域知识，默认放技能（用不到时不花钱，同领域下一个任务也能调用）；常驻记忆只放对每个任务都成立的短事实
DOM 的两条硬规矩① 绝不编造权威、编号、标准或引文；要指向有权威的来源，断言需要证据。② 写代理能执行并检查的知识，而不是背景读物：“交付前确认 X 覆盖了 A、B、C 每一项”胜过一大段说明。

“本镇才有的”与“到哪都用得上的”

提议提示词里有一段 GENERALIZE，专门讲这件事。它给了三个对照例子（原文照录）：

workspace fact   "attrition role 'HR' maps to position 'HR Manager'; 'Manager' has no
                  open requisition"                      -- verified here, labelled here
procedure        "reconcile role names explicitly before joining; list unmatched leftovers"
too generic      "be thorough"                           -- changes no behaviour
  • 工作区事实（本镇才有的）：基础执行花了代价才发现的、经过验证的事实最值钱，直接写事实本身，并用“在本工作区……”标注，让读者分得清事实和流程。猜出来的事实比没有更糟。
  • 流程（到哪都用得上的）：要按整个领域来写，因为这棵 harness 如果被选中，会存进该领域的经验库，成为后面每个任务的范例（第 5 站）。
  • 太空泛：“要仔细”——不改变任何行为。

教学解读：为什么要拆成两个维度？如果让几个编辑器读同一份证据、各自“随便改”，它们很可能挤向同一个最显眼的修复，候选之间差别很小，试探就浪费了。强制分工后，INV 候选和 DOM 候选天然互补：合成提示词也说，当一个 INV 改动和一个 DOM 改动各自站得住时，合并就是预期结果。
铜钥匙还是银钥匙？给每条观察分个类
DOM 编辑器从材料里读到“本案的申报截止日是 3 月 15 日”，想把这句写进 LongTermMEMORY.md。对吗？
B。DOM 提示词明说 “Never store this matter's facts as durable memory: they are wrong anchors for the next task.” 同时 GENERALIZE 又说验证过的工作区事实最有价值——两者不矛盾：事实可以写，但要标注清楚，而且不能当成跨任务都成立的长期记忆。
本站带走三句话
  • INV 管流程、工具和收尾；DOM 管交付物、受众、来源和一致性。两者互不越界。
  • INV 的核心是“失败类型 → 最便宜的有效部件”；DOM 的核心是“把行家知识写成可执行、可检查的规则”。
  • 工作区事实要标注；流程按领域写；空话不写。
